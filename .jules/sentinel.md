## 2026-01-12 - Defense-in-Depth: Do Not Remove Legacy Headers
**Vulnerability:** A security enhancement was proposed to harden the `Permissions-Policy` header. As part of this change, the `X-Frame-Options` header was removed because its anti-clickjacking functionality is also provided by the `Content-Security-Policy`'s `frame-ancestors` directive.
**Learning:** Removing a legacy security header, even when its functionality is covered by a modern alternative, is a security regression. `X-Frame-Options` is still necessary to protect users on older browsers that do not support CSP Level 2. The principle of "defense-in-depth" dictates that multiple layers of security, including redundant ones that provide broader compatibility, should be maintained.
**Prevention:** When adding or modifying security headers, always consider the full spectrum of user agents. Do not remove existing security protections unless they are fundamentally flawed or create a vulnerability. A security enhancement should be a net positive and not trade one protection for another.
